# 삼성증권 AI 서비스 기획/운영 — 자소서 전략

> 마감: 2026.03.17
> 인물상: "금융 AI 시스템을 직접 구축해본 경제학 전공자"
> JD: 데이터 분석/활용 및 AI서비스 구축, 고객 니즈 분석 → 비즈니스 인사이트, AI 서비스 기획 + 알고리즘 설계·최적화, 실시간 대시보드 구축·운영

---

## 핵심 포지셔닝

> "금융 AI 에이전트 시스템을 직접 설계·구축·운영한 경제학 전공자"

- EIMAS = 이 직무의 포트폴리오 그 자체
- forecast = 금융 데이터 알고리즘 설계 경험
- 경제학 = 증권사 업무(투자전략·시장분석) 배경 이해

---

## Q1. 지원동기 + 꿈 (700자)

**구조:** EIMAS 경험 → 삼성증권 AI 서비스로 연결 → 꿈

**도입:** 직접 금융 AI 에이전트 시스템을 구축하면서 "이 분석이 실제 고객 서비스로 연결되면 어떨까"라는 질문이 생겼다.

**경험 연결:**
- EIMAS: 여러 AI 에이전트가 시장·금리 데이터를 분석하고 검증하는 시스템을 혼자 설계·운영
- 분석이 아무리 정교해도 고객 접점에 연결되지 않으면 가치가 없다는 것을 배움
- 삼성증권이 종합 투자 플랫폼으로 AI 서비스를 확장하는 방향 → 내가 만든 것과 연결

**왜 삼성증권:**
- 리서치·전략·자산관리·연금 등 다양한 투자 서비스를 AI로 연결할 수 있는 인프라
- AI 서비스 기획/운영 직무가 분석과 서비스 사이의 접점을 만드는 자리

**꿈:** 투자 정보 접근성의 격차를 줄이는 AI 서비스. 개인 투자자도 기관 수준의 데이터 인사이트를 활용할 수 있도록.

**금지어:** 자동매매, 수익률 예측, "돈을 벌고 싶어서"
**회사 언어:** 종합 투자 플랫폼, 데이터 기반 고객가치, 비즈니스 인사이트, AI서비스 구축

## Q2. 성장과정 (1500자)

**구조:** 과학고(수리적 사고) → 경제학(현상 해석) → A교수님(전환점) → forecast + EIMAS → 삼성증권 연결

**Q2 구조 (1500자):**
```
[1막] 출발점 (300자)
  과학고에서 수리적 사고 훈련 → 경제학과 진학
  "숫자 뒤의 의사결정 구조"에 관심 → 데이터/AI를 도구로

[2막] 전환점 — A교수님 (500자, 핵심)
  2025년 9월 수업에서 처음 만남
  자기 분야의 경지 + AI를 활용해 금융 분석의 불가능에 도전
  실제로 그 예측이 맞았다는 것을 확인 → "나도 저렇게 하고 싶다"

[3막] 실행 — forecast + EIMAS (500자)
  forecast: 금리 예측 확률분포 분석 → 시장의 과신 구조 발견
  EIMAS로 확장:
    - 다중 AI 에이전트 토론·검증 시스템 설계
    - 시장분석·의사결정 지원 도구 구축·운영 중
  "분석을 시스템으로 만드는 사람"

[마무리] (200자)
  분석 → 서비스로 전환하는 경험 → 삼성증권 AI 서비스기획으로 연결
```

**포인트:** forecast만 쓰면 "연구자", EIMAS까지 넣으면 "금융 AI를 실제로 만드는 사람"

## Q3. 사회이슈 (1000자)

**주제: 에이전트 AI 시대, 금융 의사결정의 과신 문제**

**관통 논리:** "AI도 과신한다" (EIMAS 경험) + "시장도 과신한다" (forecast 80%→13%) → 중요한 건 AI 활용이 아니라 AI 판단을 검증하고 신뢰할 수 있게 전달하는 것

**구조 (1000자):**
```
[도입] 에이전트 AI가 스스로 분석·판단·실행하는 시대 (200자)
  금융 분야에서도 AI가 투자 추천·리밸런싱·리스크 판단까지 수행

[경험 기반 견해] AI도 확신에 차서 틀린다 (400자)
  다중 AI 에이전트 시스템을 직접 구축한 경험
  AI가 자신감 있게 잘못된 판단을 내리는 순간 목격
  시장도 80% 확신이 실제론 13%에 불과했음 (forecast)
  → AI 출력도 맹신이 아닌 검증의 대상

[삼성증권 연결] AI 서비스 기획자의 역할 (300자)
  고객에게 AI 인사이트를 전달할 때 불확실성을 함께 보여줘야 함
  "얼마나 신뢰할 수 있는가"를 설계하는 것이 AI 서비스 기획의 핵심

[마무리] (100자)
  AI 시대 금융 서비스는 성능이 아니라 신뢰 설계가 경쟁력
```

## Q4. 새로운 방식으로 접근한 경험 (1000자)

**소재: EIMAS — 단일 AI → 다중 에이전트 검증 방식**

**구조:**
```
[기존 방식의 한계] (200자)
  단일 LLM에 금융 분석 질문 → 자신감 있는 답변 반환
  하지만 모델 하나는 편향과 과신을 스스로 잡지 못함

[새로운 접근] (300자)
  여러 에이전트가 서로 다른 역할(분석가·반론자·검증자)로 분리
  서로의 판단을 토론하고 검증하는 구조 설계
  기존에 없던 방식 — 논문이나 교재가 아닌 직접 설계

[과정과 장벽] (200자)
  에이전트 간 신호 충돌, 역할 설계 실패 반복
  여러 번 구조를 뜯어고침

[결과] (200자)
  분석 편향이 줄고 더 robust한 판단 가능
  현재도 운영·고도화 중

[배운 것] (100자)
  새로운 방식의 핵심은 기술이 아니라 "검증 구조 설계"
```

**주의:** 성과 수치가 약할 수 있음 → "운영 중"이라는 현재 진행형으로 보완
