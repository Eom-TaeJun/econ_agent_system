# Concept Cards: Why / When / What Changes

## 1) 데이터 전처리 (Data Preprocessing)
- 왜 필요한가: 원본 데이터 품질이 낮으면 통계와 인사이트가 왜곡됩니다.
- 언제 쓰는가: 분석 시작 직후, 모델링 이전 단계에서 항상 수행합니다.
- 대표 작업: 타입 정리, 중복 제거, 단위 통일, 범주 표준화.
- 시각적으로 확인할 것: 전처리 전/후 기초 통계표와 분포 그래프.
- 기대 변화: 해석 가능한 데이터로 변하고 재현 가능한 분석이 가능해집니다.

## 2) 데이터 타입과 파싱 오류
- 왜 필요한가: 타입 오류는 집계와 시계열 분석을 직접 망가뜨립니다.
- 언제 쓰는가: 데이터 로드 직후 `dtypes` 확인 시 항상 점검합니다. **결측치/이상치 처리보다 먼저 수행해야** 후속 분석이 올바르게 작동합니다.
- 대표 오류:
1. 날짜가 문자열로 읽힘 → `pd.to_datetime()` 변환 필요
2. 숫자 컬럼에 문자 혼입 → 강제 변환 후 NaN 확인
3. 범주형 컬럼에 표기 불일치 (예: "Winter" vs "winter") → 통일 필요
- 시각적으로 확인할 것: 파싱 전/후 타입 목록, 변환 실패 건수 표, `value_counts()` 결과.
- 기대 변화: 올바른 집계와 시계열 연산이 가능해집니다.

## 3) 결측치 처리 (Missing Value Handling)
- 왜 필요한가: 결측을 무시하면 표본 편향과 계산 오류가 발생할 수 있습니다.
- 언제 쓰는가: 결측 비율과 결측 패턴을 먼저 확인한 뒤 방법을 선택합니다.
- 대표 방법:
1. 제거: 결측 비율이 매우 낮고 손실이 작을 때
2. 대체: 손실이 크거나 패턴 보존이 필요할 때
3. 그룹 대체: 시간대/카테고리 특성이 강할 때
- 시각적으로 확인할 것: 결측 히트맵, 처리 전/후 분포 비교.
- 기대 변화: 표본 수와 분포가 달라지며 핵심 지표(평균, 중앙값)가 변할 수 있습니다.

## 4) 이상치 탐지 (Outlier Detection)
- 왜 필요한가: 극단값은 평균/분산/상관을 크게 흔들어 잘못된 결론을 만들 수 있습니다.
- 언제 쓰는가: 수치형 변수의 분포 꼬리가 길거나 비정상 스파이크가 보일 때
- 대표 기준:
1. 도메인 규칙: 물리적으로 불가능한 값(예: 음수 대여량, 음수 강수량) — **항상 먼저 확인**
2. IQR: 분포 가정이 약할 때 실무에서 자주 사용
3. Z-score: 정규성 가정이 가능할 때
- 시각적으로 확인할 것: 박스플롯, 산점도, 시계열 스파이크.
- 기대 변화: 분산과 왜도가 완화되고 비교 가능성이 높아집니다.

## 5) 이상치 처리 (Outlier Treatment)
- 왜 필요한가: 탐지 이후 처리 전략을 정하지 않으면 분석이 불안정합니다.
- 언제 쓰는가: 이상치의 원인이 입력 오류인지 실제 희귀 현상인지 구분한 뒤
- 대표 방법:
1. 제거: 명백한 오류일 때
2. 윈저라이징(cap): 데이터 손실을 줄이며 극단 영향만 줄일 때
3. 변환(log): 우측 꼬리 분포를 안정화할 때
- 시각적으로 확인할 것: 처리 전/후 박스플롯과 히스토그램.
- 기대 변화: 극단 영향이 완화되지만, 실제 희귀 패턴이 약해질 수 있습니다.

## 6) 전/후 비교 시각화 (Before/After Comparison)
- 왜 필요한가: 방법의 효과를 말로 설명하는 대신 증거로 보여주기 위해
- 언제 쓰는가: 결측/이상치 처리 후 모든 핵심 질문 분석 단계에서
- 필수 원칙:
1. 같은 축 범위
2. 같은 단위
3. 같은 집계 수준
- 기대 변화: 처리 방법 선택의 타당성을 제3자가 빠르게 검증할 수 있습니다.

## 7) 파생 변수 생성 (Feature Engineering)
- 왜 필요한가: 원본 변수만으로는 숨어있는 패턴이 드러나지 않을 수 있습니다.
- 언제 쓰는가: 도메인 지식을 기반으로 새 변수가 예측력을 높일 것으로 기대될 때
- 대표 유형:
1. 시간 기반: 시간대 구간(새벽/출근/오후/퇴근/야간), 요일, 계절, 공휴일 여부
2. 비율·차이: 전일 대비 변화율, 평균 대비 비율
3. 결합: 두 변수를 합산하거나 나눈 값 (예: BMI = 체중/신장²)
- 시각적으로 확인할 것: 파생 변수별 수요 분포 (구간별 막대/박스플롯)
- 주의: Date 컬럼이 결측이거나 파싱되지 않으면 시간 기반 파생 변수 생성 불가 → Q2 타입 오류 처리 순서가 Q7에 영향을 줍니다.

## 8) 분포 진단 (Distribution Diagnostics)
- 왜 필요한가: 분포 형태에 따라 요약 통계량의 해석과 후속 검정 방법이 달라집니다.
- 언제 쓰는가: 분석 시작 시 타깃 변수 및 주요 수치형 변수에 대해 항상 수행합니다.
- 대표 지표:
1. Skewness(왜도): 0에 가까우면 대칭, 양수면 우측 꼬리, 음수면 좌측 꼬리
2. Kurtosis(첨도): 0 기준, 양수면 뾰족(heavy tail), 음수면 납작
3. Shapiro-Wilk 검정: p > 0.05면 정규 분포 가정 가능
- 시각적으로 확인할 것: 히스토그램 + Q-Q plot (대각선에서 벗어난 정도)
- 기대 변화: 정규성이 기각되면 비모수 검정(Mann-Whitney U 등)을 선택하게 됩니다.

## 9) 가설 검정과 효과 크기 (Hypothesis Testing & Effect Size)
- 왜 필요한가: "차이가 있다"와 "차이가 우연이 아니다"는 다른 주장입니다. 통계적 유의성을 확인해야 결론의 신뢰도가 올라갑니다.
- 언제 쓰는가: 전처리 전/후 비교(Q4, Q6), 변수 간 상관(Q9) 등 두 분포나 관계를 비교할 때
- 대표 방법:
1. 모수 검정(t-test): 정규 분포 가정이 가능할 때
2. 비모수 검정(Mann-Whitney U): 정규성 기각 또는 순서형 데이터일 때
3. 상관 유의성: Pearson r의 p-value 보고
- 효과 크기 해석 (Cohen's d):
1. |d| < 0.2: 무시할 수준
2. 0.2 ≤ |d| < 0.5: 작은 효과
3. 0.5 ≤ |d| < 0.8: 중간 효과
4. |d| ≥ 0.8: 큰 효과
- 주의: p-value가 유의해도 효과 크기가 작으면 실질적 의미가 없을 수 있습니다. 반드시 함께 보고합니다.
- 시각적으로 확인할 것: 검정 결과 표 (검정 통계량, p-value, 효과 크기, 해석)

## 10) 다중공선성 확인 (Multicollinearity Check)
- 왜 필요한가: 설명 변수끼리 상관이 높으면 회귀 모델의 계수가 불안정해지고 해석이 어려워집니다.
- 언제 쓰는가: 상관 히트맵에서 설명 변수 간 |r| > 0.8 인 쌍이 보일 때
- 대표 방법:
1. 상관 히트맵에서 변수 간 높은 상관 쌍 식별 (예: Temperature ↔ DewPoint)
2. VIF(Variance Inflation Factor): 10 이상이면 다중공선성 의심
- 대처 방법:
1. 상관 높은 변수 중 하나를 제거
2. PCA로 차원 축소 후 주성분을 설명 변수로 사용
3. 트리 기반 모델은 다중공선성에 상대적으로 강건 → 모델 선택으로 우회 가능
- 시각적으로 확인할 것: 변수 간 상관 히트맵, VIF 표

## 11) 차원 축소 — PCA (Principal Component Analysis)
- 왜 필요한가: 변수가 많고 서로 상관이 높을 때, 핵심 축만 추출하면 정보 손실을 최소화하면서 복잡도를 줄일 수 있습니다.
- 언제 쓰는가: 설명 변수가 5개 이상이고 다중공선성이 존재할 때. 또는 고차원 데이터를 2D/3D로 시각화하고 싶을 때
- 핵심 개념:
1. 설명 분산 비율(explained variance ratio): 각 주성분이 전체 분산의 몇 %를 설명하는가
2. 누적 설명 분산: 80~90% 이상이면 충분히 정보를 보존한다고 판단
3. 로딩(loading): 각 주성분에 원본 변수가 얼마나 기여하는가 → PC1의 의미를 해석
- 사전 조건: **반드시 표준화(StandardScaler) 후 적용**. 스케일이 다른 변수에 그냥 적용하면 분산이 큰 변수가 지배
- 시각적으로 확인할 것: 설명 분산 비율 막대그래프, PC1-PC2 산점도, 로딩 히트맵

## 12) 트리 기반 변수 중요도 (Tree Feature Importance)
- 왜 필요한가: 상관 분석은 선형 관계만 포착하지만, 트리는 비선형 분기를 잡아냅니다. 두 결과를 비교하면 변수의 역할을 더 입체적으로 이해할 수 있습니다.
- 언제 쓰는가: "어떤 변수가 타깃을 가장 잘 나누는가?"를 확인하고 싶을 때
- 핵심 개념:
1. `feature_importances_`: 각 변수가 트리 분기에서 불순도를 얼마나 줄였는가의 비율
2. 깊이 제한(`max_depth=4`): 해석 가능한 트리를 만들기 위해 제한
3. 상관 순위 vs 트리 순위 비교: 순위가 다른 변수가 비선형 영향력을 갖는 변수
- 시각적으로 확인할 것: 변수 중요도 수평 막대그래프, 상관 순위 비교 표
- 주의: 이 단계는 예측 모델이 아닌 EDA 목적이므로 정확도 평가는 불필요합니다

## 13) 흔한 실수
- 중복/타입 오류를 나중에 점검해서 이미 오염된 결과로 분석을 진행함
- 결측치 제거만 하고 손실률을 보고하지 않음
- 이상치 기준값을 근거 없이 임의 지정
- 도메인 규칙 확인 없이 IQR/Z-score만 적용하여 물리적 불가능 값을 놓침
- 전/후 그래프 축을 다르게 그려 차이를 과장
- 결과 설명에서 정량 수치 없이 결론만 제시
- 정규성 검정 없이 t-test를 사용하여 잘못된 검정 결과 도출
- p-value만 보고하고 효과 크기를 무시하여 실질적 의미를 간과
- 상관계수를 보고하면서 p-value를 함께 제시하지 않음
- 다중공선성이 높은 변수를 모두 모델에 넣어 계수가 불안정해짐
- PCA 전에 표준화를 하지 않아 스케일이 큰 변수가 PC1을 지배
- 트리 변수 중요도를 "예측력"으로 오해 — EDA에서는 분기 구조 탐색 목적
