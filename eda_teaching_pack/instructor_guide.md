# Instructor Guide

## 1) 운영 목표
- 학습자가 "전처리 이유"를 말로 설명하고, "전/후 차이"를 숫자와 시각화로 증명하게 만듭니다.
- 정답 코드를 주지 않고도 올바른 분석 사고를 평가할 수 있도록 설계합니다.

## 2) 수업 흐름 (권장 120분)
1. 0-15분: 문제 브리핑과 핵심 키워드 설명
2. 15-35분: 데이터 진단(스키마 + 중복/타입 오류 정리)
3. 35-55분: 결측치 진단 및 처리 전략 비교
4. 55-80분: 이상치 탐지 및 처리 전략 비교
5. 80-105분: 파생 변수 생성 + 핵심 질문 분석
6. 105-120분: 인사이트 발표와 피드백

## 3) 문항별 의도와 체크 포인트

### Q1 데이터 스키마 점검
- 의도: 분석의 기준선 수립
- 체크: 변수 타입, 행/열 수, 수치형 요약 통계가 보고됐는가
- 피드백 포인트: 타입 파싱 누락 시 후속 분석이 흔들린다는 점 강조

### Q2 중복/타입 오류 점검
- 의도: 기본 데이터 품질 이슈의 직접적 영향 인식, 후속 분석의 기반 정리
- 체크: 중복 건수와 날짜 파싱 오류를 찾아 수정했는가, 범주형 표기 불일치를 발견했는가
- 피드백 포인트: 이 단계를 건너뛰면 Q4 결측 처리의 group_median이 오염되고, Q7 파생 변수 생성이 실패할 수 있음을 강조

### Q3 결측치 진단
- 의도: 결측 "양"뿐 아니라 "패턴" 인식
- 체크: 결측 비율 표 + 결측 패턴 시각화가 함께 있는가
- 피드백 포인트: 결측률이 낮아도 특정 구간 편중이면 위험

### Q4 결측치 처리 전략 비교
- 의도: 방법 선택의 트레이드오프 이해
- 체크: `drop`과 `group_median`을 같은 지표로 비교했는가
- 피드백 포인트: 표본 손실률과 분포 변화를 함께 보게 유도

### Q5 이상치 탐지
- 의도: 탐지 기준의 근거화
- 체크: 도메인 규칙 위반 값(음수 대여량 등)을 먼저 확인했는가, IQR 또는 Z-score 정의를 명시했는가
- 피드백 포인트: "이상치 = 무조건 제거"가 아님을 명확히 지도

### Q6 이상치 처리 전략 비교
- 의도: 제거 vs 절단(cap)의 차이 체감
- 체크: 평균/중앙값/IQR 변화가 정량 보고되었는가
- 피드백 포인트: 희귀 이벤트 보존 필요성에 대한 토론 유도

### Q7 파생 변수 생성
- 의도: 도메인 친화형 설명 변수 구성
- 체크: 시간대/주말/계절 등 파생 변수가 인사이트에 기여했는가
- 피드백 포인트: 원본 변수만으로는 숨은 패턴이 드러나지 않을 수 있음

### Q8-Q9 핵심 질문 분석
- 의도: 처리 전/후 결과 차이를 질문 기반으로 해석
- 체크: 같은 축으로 before/after를 비교했는가
- 피드백 포인트: 그래프 설명이 질문에 직접 답하고 있는지 확인

### Q10 결론/권고안
- 의도: 분석 결과의 실행 가능성 평가
- 체크: 사실-근거-제안 구조가 갖춰졌는가
- 피드백 포인트: "무엇을 해야 하는가"까지 문장으로 완결시키기

## 4) 빠른 채점 기준 (현장용)
- A: 근거 기반 비교가 명확하고 전/후 차이를 정량화함
- B: 분석 흐름은 맞지만 정량 보고 또는 근거 설명이 약함
- C: 그래프 나열 중심, 질문-결론 연결이 약함
- D: 전처리 절차/근거가 부재하거나 재현성이 낮음

## 5) 실제 데이터 기반 피드백 포인트

강의자가 미리 알고 있어야 할 실제 데이터의 특성입니다 (학습자에게 직접 공개 X).

### 데이터 실측값 (raw_dirty.csv)
| 항목 | 값 |
|------|-----|
| 총 행 수 | 8,803 (중복 43행 포함) |
| 결측 컬럼 | Date·Visibility·SolarRadiation·Seasons·FunctioningDay·Rented Bike Count (각 ~3%) |
| 총 결측 셀 | 1,578 |
| drop 시 손실 | **약 1,464행 (16.6%)** — Date 결측이 다른 결측과 겹쳐 예상보다 훨씬 큰 손실 |
| 음수 대여량 | **45행** — 물리적 불가능 값 (도메인 규칙 이상치) |
| 범주형 오염 | Seasons에 소문자 표기 혼입 (예: "winter", "summer") — Q2에서 발견해야 함 |
| IQR 이상치 | 91행 (1.03%) |
| 수요 피크 시간 | **18시** (361.6대) / 2위 **8시** (354.2대) — 출퇴근 패턴 |
| 수요 최저 시간 | **0시** (150.6대) |

### 학습자 반응 예측 및 개입 포인트
- **Q2에서 범주 불일치를 놓치는 경우**: "Seasons의 `value_counts()`를 보세요. 같은 계절인데 다르게 집계되는 항목이 있지 않나요?"
- **drop 손실률이 너무 크다고 놀라는 경우**: "Date 결측 행이 261행 있어서 그 행들이 모두 제거됩니다. 그래서 drop은 이 데이터에서 특히 비효율적인 전략입니다."
- **음수를 발견하지 못한 경우**: "IQR만 보면 음수가 이상치로 잡히지 않을 수 있습니다. 먼저 값의 물리적 범위를 확인하는 습관을 들이세요."
- **피크가 18시·8시인 이유를 모르는 경우**: "이 데이터는 서울 공공자전거입니다. 어떤 사람들이 자전거를 탈까요? 출퇴근 패턴과 연결해 생각해보세요."

## 6) 자주 나오는 오해와 개입 멘트
- 오해: "결측치는 많지 않으니 그냥 삭제해도 된다"
- 개입: "삭제 후 어떤 구간 데이터가 더 많이 사라졌는지 먼저 보세요"

- 오해: "박스플롯 바깥은 다 에러다"
- 개입: "실제 이벤트일 가능성도 있으니 도메인 맥락으로 확인해보세요"

- 오해: "그래프 두 개가 다르면 처리 효과가 크다"
- 개입: "축 범위가 같은지 먼저 확인하고 수치로도 검증하세요"

## 7) 산출물 최소 요건 리마인드
- 비교 그래프 6개 이상
- 행 수/결측률/평균/중앙값/IQR 변화 보고
- 인사이트 3개 + 운영 제안 1개 + 한계 2개
