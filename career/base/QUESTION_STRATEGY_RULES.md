# QUESTION STRATEGY RULES

문항 수가 많을 때 같은 경험과 같은 결론이 반복되는 문제를 막기 위한 규칙이다.

## 기본 원칙

- 문항마다 "이 질문에서 증명할 한 가지"를 먼저 적는다.
- 문항마다 주력 사례는 가능하면 1개로 정한다.
- 같은 경험을 여러 번 써도 질문마다 꺼내는 장면과 결론이 달라야 한다.
- 문항별 역할을 먼저 나누고 그 뒤에 사례를 배정한다.

## 문항 역할 예시

- 지원동기
- 직무 적합성
- 문제 해결
- 협업과 조율
- 성장 과정
- 입사 후 기여

## 문항 분배 절차

1. 문항 원문에서 평가 포인트를 뽑는다.
2. 각 문항의 한 줄 목표를 적는다.
3. `STORY_BANK.md`에서 사례 후보를 고른다.
4. 각 문항의 주력 사례를 배정한다.
5. 사례가 겹치면 질문마다 다른 장면과 다른 메시지를 적는다.
6. 그 뒤에만 초안을 쓴다.

## 중복 판정 체크

- 두 문항이 같은 경험의 같은 장면을 말하는가
- 두 문항이 같은 강점 문장을 반복하는가
- 회사와 직무에 맞춘 번역 없이 원래 프로젝트 설명이 남아 있는가
- 여러 문항이 모두 "구조화", "소통", "문서화" 같은 같은 결론으로 끝나는가

## 질문별 설계 출력 형식

질문 n

- 평가 포인트:
- 이 문항에서 증명할 한 가지:
- 주력 사례:
- 이 문항에서 꺼낼 장면:
- 강조할 행동:
- 결과 또는 배운 점:
- 다른 문항과 겹치면 안 되는 점:
- 마지막 한 줄:

## 전략 전달 섹션 (QUESTION_MAP 하단에 필수)

QUESTION_MAP 끝에 아래 섹션을 반드시 포함한다.
이 섹션은 STRATEGY.md의 구체 지침을 Draft Writer에게 직접 전달하는 역할이다.
Strategy Designer가 QUESTION_MAP을 작성할 때 STRATEGY.md에서 아래 항목을 옮겨 적는다.

```
## 전략 → 초안 전달 체크리스트

### 초안에 반드시 녹일 회사 언어
- (STRATEGY.md의 회사/직무 해석에서 뽑은 구체 용어와 표현)

### 경험별 번역 지침
- 경험 n: (원래 서사) → (초안에서 써야 할 직무 언어 표현)

### 초안에서 피할 방향
- (STRATEGY.md의 피해야 할 방향에서 가져온다)

### 전면에 둘 역량 vs 보조로만 둘 역량
- 전면:
- 보조:

### 초안 완료 후 자가 점검
- [ ] 위 회사 언어가 초안에 최소 1회 이상 등장하는가
- [ ] 경험별 번역 지침대로 표현이 바뀌었는가
- [ ] 피할 방향에 해당하는 문장이 없는가
- [ ] 보조 역량이 전면 역량보다 부각되지 않았는가
```

## 수정 우선순위

- 전략 불일치 수정이 문장 다듬기보다 우선이다.
- 문항 중복 제거가 표현 개선보다 우선이다.
- fit이 약하면 문장을 고치기 전에 사례 배정부터 다시 한다.
